# Brave filtering source review for Pulse v1.7

This is a targeted static review of Brave's public filtering and Android YouTube integration, not a complete browser audit or a live ad-blocking test. Reviewed source: `brave/brave-core` revision `8ffa8d7f121c7b5be5ed81eefa7fd8e45de6aa85`. The source was read separately; no Brave implementation was copied into Pulse. Source behavior at this revision is not a guarantee for every shipped Brave version or every YouTube response.

## Why Pulse still shows ads

Pulse uses Android System WebView, whose application hooks do not expose Brave's full Chromium network and renderer integration. Pulse currently has a small bundled host/path matcher plus targeted document-start player-response and cosmetic scripts. It has no general ABP-compatible rule compiler, maintained component-list distribution, general scriptlet/resource catalog, or Brave renderer integration. The presence of a skip control or removed metadata field is not proof that an ad was prevented. Server-delivered responses, same-stream content, website changes and injection timing can defeat the current approach.

Pulse v1.7 does not change that filter implementation. Its fixes address player colors, clock text and the native audio spectrum. Existing local filter diagnostics and the filtering off switch remain available. No all-ads-blocked, Premium entitlement, protected-media download or verified screen-off continuity claim is made.

## What a larger integration would require

A stronger blocker would require choosing a maintained engine with compatible licensing, integrating request context and exceptions, shipping trusted versioned lists/resources with rollback, and testing navigation, login, playback and failure modes across real WebView/device versions. A custom Chromium browser engine would additionally require its own continuing browser security updates and a much larger build/distribution system. Dropping one Brave script into this app would not supply those layers.

Downloaded filters and injected scripts are executable or behavior-changing input. A future updater needs a constrained trusted source, authenticated artifacts, bounded downloads and last-known-good rollback. Broadly blocking Google video or authentication hosts can break playback/login; hiding an element must not cover permission/security prompts. Pulse retains HTTPS verification, restricted navigation and no native JavaScript bridge. This review is not an independent security assessment of Pulse, Brave, Google or uploaded modified APKs.

## Validation boundary

Public source inspection establishes the architecture and specific call paths described here. No Brave APK was instrumented, no complete dependency audit was performed, and live signed-in/signed-out YouTube ads were not tested on a phone. Pulse's JavaScript fixtures test controlled inputs only. Claims about current real-world ad suppression require device/network testing and cannot be inferred from a successful build.
